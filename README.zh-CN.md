# YueYun Safehouse — Evidence First

[English](README.md) | **简体中文**

**面向用户控制的 AI 披露、授权记录与可验证证据的开放倡议。**

**状态：**早期研究倡议 · 尚无 Safehouse 参考实现 · 无独立安全认证

目前由一位发起人维护，治理机制与名称使用规则尚未确定。本地发布材料等待人工验收，尚未公开发布。本仓库拟作为面向全球开发者的简洁工程协作入口；跃云白皮书 3.0 拟承载完整思想、社会机制与长期框架，本目录不包含该白皮书，也未独立核对其正文。

## 问题

随着 AI 代理越来越多地使用个人记忆并代表人行动，用户需要能够独立于服务提供方保留的证据。

三个问题尤为重要：

**谁收到了什么？谁批准了这次使用？用户能保留什么证据？**

Safehouse 探索开放、由用户控制的 AI 交互证据层。

## 一个简单示例

用户允许 AI 服务为旅行规划使用两条明确选择的记忆。

例如，完全虚构的 Mira 有三条记忆：“Mira 计划去京都旅行”“Mira 喜欢轻松旅行”和“Mira 喜欢黑咖啡”。用户只选择前两条旅行记忆，咖啡偏好保持排除。这个例子用于解释研究目标，不是 Safehouse 已实现功能的声明。

- 第三条记忆仍被排除。
- 用户本地记录标识授权范围、接收方、用途与决定。
- 如果发生披露，其状态与授权分别记录。
- 如果接收方提供签名确认，用户可以比对双方记录。

此例展示拟议协议，并不表示接收方确认已经实现。

## 三个拟议构件

### 1. 披露标记 / Disclosure Marker

仅针对某次披露的标识，拟用于来源追溯，而不成为跨服务跟踪标识。

**状态：概念。**标记的持久性、隐私影响及对数据可用性的影响仍未测试。

### 2. 用户侧证据账本

由用户控制，记录授权决定、披露事件与可取得的交付证据。

可能采用的机制包括加密本地存储、哈希链、可独立验证的证明以及批量时间戳锚定。

**状态：相关本地原型已经进行限定范围作者操作测试。**具有密码学链及外部锚定的 Safehouse 账本尚未实现。

### 3. 签名回执与对账

接收服务可以签署确认，将披露的信息与约定用途、期限、转交及模型训练等使用条件关联。

用户随后可以比对该确认与自己的记录。

**状态：概念。**本项目没有已经验证的接收方签名或跨方对账实现。

## 设计原则

- 用户控制与最少必要披露。
- 清楚区分授权、消费、交付与签收。
- 接收方不参与时，用户侧记录仍可使用。
- 共享审计证据不存储不必要的个人内容。
- 不自创密码学，不声称绝对安全。
- 开放规范与可独立实现的接口。
- 实现声明同时提供测试与限制。

## 架构边界

- **YMIS：**记忆、仅供审计的授权决定与审计回执的信息交换规范。
- **Safehouse：**拟议的权限执行、隔离工作环境、用户审查与证据处理。
- **人格公网：**拟议的服务发现、代理人应答、交易与结算。

各层不自动赋予彼此权限。历史批准不是可迁移、可消费的 grant。Safehouse 的职责是研究目标，不是已经实现的安全能力。

Memory ≠ Permission。Approve ≠ Consume ≠ External Disclosure。
Pre-consumption Revoke ≠ Post-consumption Recall。
Context Ready ≠ External Model Received。Completed ≠ External Model Answered。

## 拟议符合性研究

早期规范草案提出十项测试，覆盖授权范围、不可信输入、一次性权限、过期与撤销、被排除的记忆、账本完整性、删除、回执对账、安全设置变更及跨模型行为。

这些是**拟议测试，不是已经完成的 Safehouse 认证标准**。

参见[规范讨论草案](docs/specification-draft.md)及[验证范围](docs/validation/README.md)。

## 相关工作

Safehouse 拟补充现有授权与代理互通方法，而不是替代它们。

相关工作包括：

- [OAuth 2.1](https://datatracker.ietf.org/doc/draft-ietf-oauth-v2-1/)：委托授权。
- [Model Context Protocol](https://modelcontextprotocol.io/)：模型、工具与服务互通，包括授权机制。
- 代理委托、回执与可携带记忆方法：尚待进一步核对原始来源。

以上是原稿中的相关工作概述；本轮未核对外部来源或当前版本。逐项核对状态见[相关工作清单](docs/related-work.md)。

Safehouse 拟关注**用户控制的证据记录、披露标记及接收方对账层**。目前不声称与这些标准兼容。

## 非目标与限制

Safehouse 不是集中式个人数据平台、支付网络或代币化项目，也不替代服务提供方自身的隐私与安全责任。

用户侧日志不能单独证明外部接收或接收方遵约。已经披露的信息可能无法从外部系统追回或删除。证据能否被采信取决于适用法律与具体情形。

本项目不是法律意见、最终标准或安全认证。不声称已实现操作系统身份认证、可信显示或同用户恶意软件隔离；不承诺远端签收、远程删除或绝对安全。
