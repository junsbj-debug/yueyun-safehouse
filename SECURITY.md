# Security

Safehouse is currently a documentation initiative with no reference implementation. There is no supported production version, security certification or guaranteed incident-response service.

## Reporting sensitive concerns

GitHub Private Vulnerability Reporting is the preferred proposed channel. **Its availability has not been verified and it is not declared enabled.** Before public launch, the maintainer must enable and test it on the actual repository and update this document.

If an actual repository shows an available private reporting option in its Security area, use it only after confirming it belongs to the intended repository. If no verified private channel is available, do not publish exploit details or sensitive attachments. A public issue may ask for a private contact route using only a non-sensitive summary; wait for the maintainer to establish that route. No placeholder email is provided.

Do not send credentials, personal memories, identifiable conversations, raw audits or full Context. Use minimal invented examples, describe impact and affected document version, and keep sensitive details out of titles. Do not access other people's data or test systems without authorization.

## Boundaries

Local approval, generation, copying and external receipt are different events. A local record is not a remote signature. Nothing here guarantees remote deletion, confidentiality on a compromised host, OS identity verification or isolation from malicious software running as the same user.

Maintainer confirmation of a report is not a promised fix date or certification. See the [threat model](docs/threat-model.md).
